  <action>
    **1. Create `src/models.py`** — Pydantic models for API requests:
    - `ChatRequest`: `message: str`, `session_id: str | None = None` (auto-generated if omitted)
    - `ApproveRequest`: `state_id: str`, `approved: bool`, `session_id: str`
    - `ChatStreamRequest`: Query params model for the SSE GET endpoint — `message: str`, `session_id: str`

    **2. Create `src/sessions.py`** — In-memory session store (CHAT-03):
    - `SessionStore` class with an in-memory dict mapping `session_id` to conversation history (list of message dicts)
    - `get_or_create_session(session_id: str) -> list` — returns existing session history or creates a new empty one
    - Include a `FireflyClient` per session (research Pitfall 4: not thread-safe to share across requests). Each session stores a `FireflyClient` instance alongside the conversation history.
    - Session data structure: `{"messages": [...], "client": FireflyClient(...), "created_at": datetime, "pending_state": None}`
    - Session TTL: 30 minutes of inactivity, cleanup via a simple check on each access
    - Thread-safety: Use `asyncio.Lock` per session if needed for concurrent access within a session

    **3. Create `src/approval.py`** — Approval state management (SAFE-01, SAFE-02):
    - `store_state(state, session_id: str) -> str` — stores the serialized agent state keyed by session_id (since approval is per-session), returns the state_id (which is the session_id for simplicity)
    - `load_state(state_id: str) -> state` — loads and removes the stored state
    - `format_approval_preview(interruptions) -> dict` — formats the interruptions into a human-readable preview dict. For each interrupted tool call, extract: tool name, arguments (what will change), and a natural language summary (e.g., "Update category of transaction 'abc123' to 'Groceries'")
    - Cleanup: States older than 10 minutes are discarded on access

    **4. Create `src/app.py`** — FastAPI app:
    - `app = FastAPI(title="Finance Analyzer")`
    - Lifespan handler to initialize `SessionStore`
    - Mount static files from `src/static/` at `/static`
    - Include chat router from `src/chat.py`
    - CORS middleware for development (allow all origins)
    - Health check endpoint at `GET /` returning `{"status": "ok"}`

    **5. Create `src/chat.py`** — Chat endpoints with SSE streaming (CHAT-01, CHAT-02):
    - `GET /chat/stream` — SSE streaming endpoint:
      - Accepts query params: `message` (required), `session_id` (required)
      - Uses `sse_starlette.EventSourceResponse` with an async generator
      - Gets session from `SessionStore`
      - Appends user message to session history
      - Runs `Runner.run_streamed(finance_agent, messages=session_history, context=RunContextWrapper(client=session.client))`
      - Streams events:
        - `response.output_text.delta` → emit `event: text`, `data: {"content": delta}`
        - `response.function_call_arguments.done` → emit `event: tool_call`, `data: {"name": name, "arguments": args}`
        - When `result.interruptions` is non-empty → emit `event: approval_needed`, `data: {"preview": format_approval_preview(interruptions), "state_id": store_state(state)}`, then close stream
        - `response.completed` (without interruptions) → emit `event: done`, `data: {}`, append assistant response to session history
        - Any exception → emit `event: error`, `data: {"message": natural_language_message}` (CHAT-04: catch exceptions and translate to user-friendly messages, never expose stack traces)
      - Uses `async for event in result.stream_events():` pattern from research

    **Important implementation notes:**
    - The Agents SDK `Runner.run_streamed()` API signature may differ from research code. Verify exact parameters during implementation by checking the installed SDK docs.
    - The `RunContextWrapper` needs to carry the `FireflyClient` so that function_tool wrappers can access it. Research shows `context.client` pattern — ensure this is set up correctly.
    - SSE event names must match what the frontend expects. Use simple names: `text`, `tool_call`, `approval_needed`, `done`, `error`.
    - For error handling (CHAT-04): Wrap the entire `event_generator` in try/except. Catch `Exception` and emit `event: error` with a generic natural language message. Never expose exception type, traceback, or API error codes.

    **6. Add dependencies:** `uv add fastapi sse-starlette uvicorn`

    **1. Add approval endpoint to `src/chat.py`** (SAFE-01, SAFE-02):
    
    - `POST /chat/approve` — Approval endpoint:
      - Accepts `ApproveRequest` JSON body: `{state_id, approved, session_id}`
      - Loads session and stored state via `load_state(state_id)` and `SessionStore.get(session_id)`
      - If `approved` is True: call `state.approve()` for each interruption in the stored state
      - If `approved` is False: call `state.reject()` for each interruption
      - Resume the agent by continuing the run: `Runner.run(finance_agent, state=state, context=RunContextWrapper(client=session.client))`
      - Return `{"response": result.final_output, "session_id": session_id}` as JSON
      - On error: return `{"error": "natural language message"}` — never expose stack traces (CHAT-04)
      - Update session history with the agent's final response after approval/rejection
