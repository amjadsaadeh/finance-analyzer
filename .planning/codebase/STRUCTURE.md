## Directory Purposes

**Root (`/`):**
- Purpose: Contains all application source — single-module design, no `src/` directory
- Contains: Python modules, project config, documentation
- Key files: `tools.py`, `main.py`, `pyproject.toml`, `AGENTS.md`

**`tests/`:**
- Purpose: All unit tests, co-located in a separate directory (not co-located with source)
- Contains: Single test file `test_tools.py` plus `__init__.py`
- Key files: `tests/test_tools.py`

**`docs/plans/`:**
- Purpose: Design documents and planning artifacts with date-prefixed filenames
- Contains: Markdown design docs
- Key files: `docs/plans/2026-05-05-llm-tools-design.md`

**`docs/superpowers/plans/`:**
- Purpose: Plan artifacts generated by the superpowers skill system
- Contains: Dated plan markdown files
- Key files: `docs/superpowers/plans/2026-05-05-firefly-llm-tools.md`

**`.planning/`:**
- Purpose: GSD (Get Stuff Done) planning documents including codebase analysis
- Contains: `codebase/` subdirectory with analysis docs (this file)
- Key files: `.planning/codebase/ARCHITECTURE.md`, `.planning/codebase/STRUCTURE.md`

## Key File Locations

**Entry Points:**
- `tools.py`: Core module — exports `FireflyClient`, `dispatch`, `get_tools`, `TOOLS`, `_HANDLERS`
- `main.py`: Stub entry point — not used in practice; the real entry is an external agent loop importing from `tools.py`

**Configuration:**
- `pyproject.toml`: Project metadata, dependencies (`firefly-iii-api-client>=6.2.21.0`, `openai>=2.34.0`), dev deps (`pytest>=8.0.0`), pytest config (`testpaths = ["tests"]`)
- `.python-version`: Python 3.12 (used by `uv`)
- `uv.lock`: Deterministic lockfile for all dependencies
- `.gitignore`: Standard Python ignores (`__pycache__/`, `.venv`, build artifacts)

**Core Logic:**
- `tools.py`: All business logic — client wrapper, 13 tool schemas, 13 handlers, 3 helpers, dispatch registry

**Agent/Documentation:**
- `AGENTS.md`: Machine-readable agent instructions (commands, architecture summary, testing patterns, env vars)
- `CLAUDE.md`: Claude Code project instructions (project layout, tool reference, testing guidance)

**Testing:**
- `tests/test_tools.py`: All 31 tests — FireflyClient tests, per-tool handler tests, dispatch/get_tools integration tests

**Design Docs:**
- `docs/plans/2026-05-05-llm-tools-design.md`: Original design doc for the LLM tools architecture

## Naming Conventions

**Files:**
- Source modules: `snake_case.py` (e.g., `tools.py`, `main.py`)
- Test files: `test_{module}.py` (e.g., `test_tools.py`)
- Config files: lowercase with dot-prefix or standard names (e.g., `pyproject.toml`, `.python-version`, `.gitignore`)
- Design docs: date-prefixed kebab-case (e.g., `2026-05-05-llm-tools-design.md`)

**Directories:**
- Lowercase: `tests/`, `docs/`
- Dot-prefix for tooling: `.planning/`, `.venv/`

**Within `tools.py`:**
- Tool schema classes: `PascalCase` BaseModel subclasses (e.g., `ListTransactions`, `GetTransactionsByDateRange`)
- Handler functions: `_handler_{snake_case_tool_name}` (e.g., `_handler_list_transactions`, `_handler_update_transaction_tags`)
- Helper functions: `_snake_case` (e.g., `_build_split_update`, `_fetch_net`, `_insight_total`)
- Tool names (in dispatch): `snake_case` (e.g., `list_transactions`, `get_expense_insights`)
- Constants: `UPPER_SNAKE_CASE` (e.g., `TOOLS`, `_HANDLERS`)

## Where to Add New Code

**New Tool:**
- Schema class: Add `PascalCase` BaseModel subclass in `tools.py` after the existing schemas (~line 158, before `TOOLS` list)
- Handler function: Add `_handler_{tool_name}` in `tools.py` after existing handlers (~line 588, before `_HANDLERS` dict)
- Register schema: Add `pydantic_function_tool(YourModel, name="tool_name")` to `TOOLS` list (~line 160)
- Register handler: Add `"tool_name": _handler_tool_name` to `_HANDLERS` dict (~line 591)
- Tests: Add test functions in `tests/test_tools.py`, following the `@patch("tools.ApiClassName")` pattern

**New Helper/Utility:**
- Private helpers: Add `_snake_case` function in `tools.py` near related handlers (e.g., `_build_split_update` is near the write handlers, `_insight_total` is near the calc handlers)
- If module grows too large: split into a `tools/` package, but this is not currently needed

**New Configuration:**
- Dependencies: Add to `pyproject.toml` `[project.dependencies]` or `[dependency-groups.dev]`
- Env vars: Document in `AGENTS.md` and `CLAUDE.md`; read in `FireflyClient.__init__`

**New Tests:**
- Add test functions to `tests/test_tools.py` following existing patterns
- No additional test files are needed unless the module splits into a package

## Special Directories

**`.venv/`:**
- Purpose: Python virtual environment managed by `uv`
- Generated: Yes (`uv sync --dev`)
- Committed: No (gitignored)

**`__pycache__/`:**
- Purpose: Python bytecode cache
- Generated: Yes (automatic)
- Committed: No (gitignored)

**`.planning/`:**
- Purpose: GSD planning artifacts (codebase analysis, phase plans)
- Generated: Partially — analysis docs are hand-written, phase plans are generated
- Committed: Yes

**`docs/`:**
- Purpose: Design and planning documents
- Generated: No (manually authored)
- Committed: Yes
