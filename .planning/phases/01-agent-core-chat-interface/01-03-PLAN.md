  <action>
    **1. Create `src/static/index.html`** — Minimal but functional chat UI (CHAT-01):

    A single HTML file with embedded CSS and JavaScript. No build tooling required.

    **Layout:**
    - Dark background with a centered chat container (max-width 800px)
    - Message display area at top (scrollable, flex-grow)
    - Input area at bottom (fixed): text input + send button
    - Approval panel (hidden by default): shows preview text + Confirm/Cancel buttons

    **JavaScript functionality:**
    - `sessionId` generated via `crypto.randomUUID()` on page load (CHAT-03)
    - `pendingStateId` variable to track approval state
    - `sendMessage(message)` function:
      - Clear input, add user message to chat display
      - Create `new EventSource("/chat/stream?session_id=${sessionId}&message=" + encodeURIComponent(message))`
      - On `text` event: append content to the latest assistant message div
      - On `tool_call` event: display a subtle "Using tool: {name}" indicator
      - On `approval_needed` event: parse preview and state_id, show approval panel with preview text, store `pendingStateId`, close EventSource
      - On `done` event: close EventSource
      - On `error` event: display error message in chat (natural language, not raw)
      - On EventSource `error` event (connection error): display "Connection lost. Please try again."
    - `respondToApproval(approved)` function:
      - POST to `/chat/approve` with `{state_id: pendingStateId, approved: approved, session_id: sessionId}`
      - On success: display the agent's response in chat, hide approval panel
      - On error: display "Something went wrong. Please try again."
      - After approval/rejection, the response from `/chat/approve` contains `{"response": "...", "session_id": "..."}`
    - Auto-scroll chat display to bottom on new content
    - Enter key in input triggers send
    - Disabled input while waiting for response (prevent double-send)

    **Styling (embedded CSS):**
    - User messages aligned right, assistant messages aligned left
    - Different background colors for user vs assistant
    - Tool call indicators in a muted/italic style
    - Approval panel with a yellow/warning background, bold confirm and cancel buttons
    - Error messages in red
    - Clean, minimal look — this doesn't need to be polished, just functional
    - CSS Grid or Flexbox layout, no external dependencies

    **2. Update `main.py`** — Uvicorn entry point:
    - Replace the existing stub with a `main()` function that runs `uvicorn.run("src.app:app", host="0.0.0.0", port=8000, reload=True)` for development
    - Include `if __name__ == "__main__": main()` guard
    - Add docstring explaining how to run: `uv run python main.py` or `uv run uvicorn src.app:app --reload`

    **3. Ensure static file serving works:**
    - In `src/app.py`, mount `StaticFiles(directory="src/static", html=True)` at `/` (after API routes so `/chat/stream` takes priority)
    - Verify that `GET /` serves `index.html`

    Create `tests/test_integration.py` — End-to-end tests that verify the full chat flow works together:

    **These tests mock the LLM responses but exercise the full HTTP path through FastAPI.**

    Use `from fastapi.testclient import TestClient` and mock the Agents SDK `Runner` at the module level.

    1. **Test SSE streaming flow:**
       - Mock `Runner.run_streamed` to yield text delta events
       - Send `GET /chat/stream?session_id=test-session&message=How+much+did+I+spend+on+dining+last+month%3F`
       - Verify response is SSE content type
       - Verify events contain `event: text` with content deltas
       - Verify final event is `event: done`

    2. **Test approval flow:**
       - Mock `Runner.run_streamed` to yield an `approval_needed` interruption with a tool call (e.g., `update_transaction_category` with `{transaction_id: "123", category_name: "Groceries"}`)
       - Verify the SSE stream emits an `approval_needed` event with preview data
       - Then mock `Runner.run` to return a final response for the approval continuation
       - POST to `/chat/approve` with `{state_id: ..., approved: true, session_id: "test-session"}`
       - Verify response contains the agent's final message

    3. **Test rejection flow:**
       - Same setup as approval flow but POST with `approved: false`
       - Verify the agent's response acknowledges the rejection

    4. **Test session context:**
       - Send two sequential messages to the same `session_id`
       - Verify the second request includes the conversation history from the first (by checking that the session store has accumulated messages)

    5. **Test error handling (CHAT-04):**
       - Mock `Runner.run_streamed` to raise an exception
       - Verify the SSE stream emits an `event: error` with a natural language message
       - Verify the error message does NOT contain the exception type, traceback, or "Error:" prefix

    6. **Test health check:**
